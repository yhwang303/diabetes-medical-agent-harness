## 构建与打开

从 implementation 目录执行：

```bash
scripts/desktop.sh build
scripts/desktop.sh open
```

本地开发应用位于 `app/src-tauri/target/debug/bundle/macos/Medical Harness.app`，页面资源来自原生包，不需要 Vite 服务。开发包依赖构建时的本项目目录及 `.venv/bin/python`；尚未打包 Python runtime，不能搬到另一台机器当作分发安装包。

工具链/缓存位于项目 `.cache/cargo`、`.cache/rustup`、`.cache/npm`；不改用户全局环境。前端和 Cargo 依赖由 lock 文件固定。

## 使用

1. 打开应用，等待“病例接口已连接”。
2. 点击“导入 JSON 病例”，选择 UTF-8（无 BOM）、最大 64 KiB 的结构化病例。可先选择 `examples/synthetic-case.json` 合成示例。
3. Core 验证固定 SnapshotInput 合同：成人 T1D 标签、mg/dL、带时区、5 分钟等间隔、6–288 个点、准确的缺失掩码。缺失值为 null，不自动补齐或换算。
4. 保存成功后查看原始曲线及逐点表格。缺失处断线，全部缺失时不生成数值曲线；没有预测或用药解释。
5. 来源详情包含原始 source_ref 声明、病例/快照 ID、文件与快照 SHA-256。数据来源声明不是医学真实性鉴定。

病例列表显示最近 100 份。重复导入完全相同 UTF-8 内容会打开当前已保存病例（保留首次文件名）；不同所有者不能互相复用病例。API 更新了病例快照时，旧文件来源不会错误地绑定到新快照。

## 生命周期与权限

- 开发 App 自动启动自己管理的 localhost Core，端口动态分配，显式传入 `--enable-fixtures --enable-agent` 以支持工程按钮与受限报告任务；启动/只读刷新不执行任何模型。CLI 默认仍关闭 fixtures，research 模式不回退。数据、凭据与日志在 `runtime/desktop-core/`，与 CLI 默认 runtime 及 smoke 数据库隔离。
- Rust 桥接只有 `list_cases`、`input_timeline`、`import_case`、`case_evidence`、`check_prediction`、`run_rl_demo` 六种既有业务命令，并新增 agent_configuration/start/latest/status/cancel 五种受限命令；通过固定 Python HTTP 客户端调用同一受认证 API。页面拿不到 bearer、端口、任意 URL、shell 或数据库接口。
- 浏览器 Origin 拒绝和 CSP 保持启用；文件内容以原始字符串交给 Core，不由页面解析后丢失重复字段。无效编码/过大文件/不合合同的内容不入库。
- 关闭窗口隐藏并保留后台；菜单退出/Cmd+Q 结束 App 及它管理的 Core。已提交数据保留，重开从 SQLite 重新加载。当前验证覆盖正常退出重开；强制杀死 App/系统崩溃后的孤儿进程清理尚未验收，属于后续进程生命周期加固。
- 只读输入时间线与证据刷新不返回模型候选、草稿或未发布报告，也不创建任务。只有明确点击预测占位或 RL 场景按钮才创建 eval run 并执行对应占位检查。

## 证据与闸门（2026-09-10）

选择病例后切换到“证据与闸门”：六张卡分别检查输入快照、预测证据、策略证据、工程安全、双审核绑定及发布条件。状态来自 Core，只展示受控原因码、来源、引用及摘要，不返回原始模型数值、剂量、草稿或审核正文。

没有 run 时显示真实模型未配置/分析未启动；存在 run 时读取该病例最近一次 run，并重新检查当前快照、有效期、版本、作业和依赖。不会复用更早 run 的通过状态。取消、撤销、过期及改稿后不继续授予资格；fixture 明确标记为工程替身。

页面显示最近检查时间，每 5 秒刷新（文档隐藏时暂停），也可手动刷新。显示状态是一次读取快照，可能有刷新间隔；发布 API 始终重新核验。请求失败即撤下旧卡片，显示无法核验，并撤销连接标记；重新打开 App 可恢复本地服务。病例快照变化会要求重新加载病例，避免混用旧输入与新证据。

139 项后端测试通过；原生实际验证完整输入/缺失输入两病例的正确阻断，以及停止 Core 后旧卡片撤下。证据见 `runtime/desktop/evidence-http.json`、`evidence-verification.json`、`evidence-build.log`。测试不等于真实模型或医学验证。

## 预测占位检查（2026-09-10）

在完整合成病例的“证据与闸门”页点击“运行预测占位检查”。占位器只把最后一个观测值重复为 6 个点（5 分钟间隔），无训练或医学效力；页面只显示 fixture 来源和登记摘要，不展示未发布模型数值。Core 验证当前快照、来源、作业及响应绑定后登记产物，策略仍待前置，发布保持阻断。

原生客户端固定请求 eval，并传入 expected_snapshot_id；旧快照、非 synthetic 来源在 Core 创建任务前拒绝，缺失输入不会进入执行器。按钮执行中禁用，响应丢失后手动重试复用幂等键；不自动重放写请求。单步 `POST /runs/{run_id}/prediction` 只执行预测，不连带 RL、工程安全、审核或发布；正文必须为空。

最新完整回归 154 项通过；前端和离线 Tauri 构建通过。原生实点后，桌面数据库恰有 1 个 run、1 个 prediction 作业、1 份 fixture 产物，drafts/reviews/releases 均为 0，原有 2 份输入仍在；见 `runtime/desktop/prediction-verification.json` 和 `prediction-build.log`。来源声明仍不是数据真实性鉴定，真实模型执行隔离等 0R 要求未完成。

## RL fixture 故障演示（2026-09-10）

在完整合成病例的“证据与闸门”页选择 RL 场景，再点击“运行 RL 场景”。每个新演示创建独立任务，自动运行预测占位、该场景的策略占位及原有工程规则；不训练模型、不执行实际动作、不调用审核或发布。选择器改变的是下次演示，卡片下方的“当前任务场景”来自 Core 已保存的任务。

| 固定场景 | Core 实际结果 |
| --- | --- |
| 正常占位 | 双模型登记与工程检查通过，仍因未审核而禁止发布 |
| 策略弃权 / 输入不支持 / 策略返回错误 | 分别为 POLICY_ABSTAIN / POLICY_UNSUPPORTED / POLICY_ERROR，不登记策略产物 |
| 输出格式错误 | INVALID_MODEL_OUTPUT，合同拒绝，不登记策略产物 |
| 父预测错配 | FORECAST_PARENT_MISMATCH，不登记策略产物 |
| 工程边界超限 | 策略格式和依赖登记成功，但工程规则拒绝；全任务不能据此放行，不返回候选数值 |
| 执行超时 | 固定执行器实际等待超过 5 秒，Core 返回 EXECUTOR_TIMEOUT；迟到结果不登记 |

场景在创建时绑定到快照、幂等身份和受信执行器版本，并进入事件记录；每个任务独立选择，不能修改共享策略或用同一幂等键更换场景。重试同一未确认/超时请求复用键且受三次作业预算约束；改选场景后运行属于新任务。执行中两个执行按钮和场景选择器禁用。

最新回归 176 项通过（2 条既有依赖弃用提示），前端和离线原生构建通过。8 个场景均已原生实点，并与真实 HTTP 状态/数据库逐项核对；超时作业约 5.003 秒失败，迟到期限过后无策略产物。旧病例/预测数据经增量迁移保持不变。见 `runtime/desktop/rl-demo-verification.json`、`rl-before-migration.json` 和 `rl-demo-build.log`。

仍是工程 fixture：固定候选和工程边界都不是医学参数。下述新版本已改为进程终止；真实预测/RL/LLM 仍未接入。

## 独立 worker（2026-09-10）

当前开发 App 的 Core 使用独立执行进程；操作入口保持不变。预测、策略及后端审核都由进程 worker 执行，超时/取消/快照或版本失效后终止进程并回收。GUI 的旧超时记录只保留一般超时说明，避免把历史线程任务误说成已经进程终止。

本轮正常占位与超时均原生实点：正常的两个 worker 正常退出；超时的策略进程实查 PID/PPID/PGID，约 5.001 秒后被 SIGKILL，PID 已消失且无策略产物。旧数据逐字段保持不变，桌面未执行审核或发布。全量 200 项测试及离线原生构建通过；证据在 `runtime/desktop/worker-verification.json`、`worker-before.json`、`worker-build.log`。

限制及 24 项真实进程专项见 [执行隔离验收](../docs/worker-isolation.md)。当前默认阈值为工程配置，内存按 RSS 采样后终止，不能当作完整 OS 沙箱或真实模型负载验收。下一步必须实现真实 Agent SDK/LLM 任务链，现有固定按钮演示不替代 Agent 本体。
