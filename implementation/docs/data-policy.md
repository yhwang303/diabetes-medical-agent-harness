## 数据实际流向

公开 `GET /contracts` 的 `data_policy` 来自受控代码 `data_policy_catalog()`，版本为 `engineering-data-policy-v1`。它描述现有可调用链，不给未来工具自动授权。

| 接收方 | 当前接收内容 | 边界 |
| --- | --- | --- |
| 本地 Core / SQLite | 输入快照（CGM、来源声明；新合同另含治疗/实际输注历史）、导入文件名/hash、模型产物、草稿、审核、发布、授权与审计元数据 | 文件名和来源定位也可能包含身份信息；当前不能把这些当作已脱敏资料 |
| 本地预测/RL worker | Core 装配的同一快照、任务摘要；RL 另取 Core 的父预测 | 当前只执行 fixture；本次授权不解锁真实模型或外部模型服务 |
| 报告 SDK / DeepSeek 官方 Flash | 固定提示、工具 schema、模板版本、证据摘要、受控状态、章节提案、模型生成的会话内容和 SDK 协议元数据 | 报告工具不返回原始快照、文件名、来源定位、完整草稿或其他病例；不能据此宣称未来主 Agent 也已满足最小外发 |
| 预测 SDK / Flash（P03） | 固定提示/工具 schema、作业状态/错误码/ID、产物引用/hash/origin/producer/version、模型生成的会话与 SDK 协议元数据 | 新增独立 prediction 授权；无原始快照、预测数值或用户文件名，不能自行登记结果 |
| RL SDK / Flash（P04） | 固定提示/schema、job 状态/错误码/ID、候选产物引用/hash/origin/producer/version、会话和 SDK 协议元数据 | 独立 rl 授权；不发送原始快照、预测值或剂量，候选不等于安全通过 |
| medical / ethics reviewer SDK / Flash | 各自固定提示、schema、同一绑定工程报告、报告/证据摘要、run/case/snapshot/draft/revision/config 引用、结构化审核和模型生成的会话内容 | 报告含模型数值、单位、时间与转换来源，是派生资料；不含原始 CGM/用药历史。两个用途独立授权，不向其中一个发送另一审核结论 |
| 本地事件/outbox、网关与任务状态 | 受控 ID、用途、许可修订/政策摘要、状态、错误码、工具/执行器/会话元数据、请求计数/预算/用量 | 不记录任意输入、工具参数、模型自由文本或密钥；SDK 自身文件另列于下文，不与 Core 日志混称 |
| 外部 Observation | 无 | 未连接，不提供授权或上传入口，不能借报告许可外发原始 trace |

字段限制依靠 Core 装配、固定工具返回值和 SDK 工具权限实现；网关不靠关键词过滤来判断任意文本是否为个人信息。来源仍是导入者声明，`synthetic` 标签不能证明用户填入的内容一定不含真实身份资料。

## 授权与撤回

默认无许可。病例归属用户可通过下列认证 API 查看和更新；SDK/模型没有这些工具，上传快照也不能附带许可字段来取得权限。

- `GET /cases/{case_id}/data-permissions`：当前快照及 report / medical_review / ethics_review / prediction / rl 的有效状态，不返回服务实例凭据或资料正文。
- `PUT /cases/{case_id}/data-permissions`：严格请求 `snapshot_id`、`purpose`、布尔 `allowed`、固定 `policy_version`。同用户下另一病例、旧快照或别的用途不能复用。

每项许可绑定病例、当前快照、用途、政策内容摘要和本次 Core 实例。重复提交同一状态幂等；撤回再授权产生新修订。新快照或服务重启必须重新授权，启动、页面刷新和重新读取状态都不会自动授权。新服务读取旧备份时，旧许可记录仍保留，但实例绑定不再有效。

桌面报告面板显示外发说明和未预选勾选项。勾选后点击启动才提交 report 授权和任务；勾选本身、打开和刷新都不调用模型。已有授权可撤回。桌面当前尚无双 reviewer 调度，本轮不借此实现 P07；两项 reviewer 许可通过相同认证 API 管理。

ReportAgent、ReviewAgent、PredictionAgent 与 RLAgent 在读取真实密钥前检查各自用途许可。开始外发的 job 固定许可修订及内容，之后工具调用、网关每次上游请求、流式返回和 Core 接收待办结果时再次检查。桌面任务还固定排队时的许可，撤回后重新授权不能复活旧任务。权限/审计失败均停止该路径；普通本地 fixture 流程不需要 LLM 外发许可。

撤回作用于后续外发检查和待接收结果。刚刚通过检查的请求可能已经在途，已到供应商的数据无法由本地撤回；网络超时或进程回收也不等于远程删除。已经完成的审核、草稿和发布包作为历史记录保留，撤回不伪称这些记录已删除；既有发布有效性仍由原闸门核验。

## P02b：保留与删除合同

2026-09-11 批次 23 增加 `engineering-lifecycle-v1`，由公开 catalog 的 `data_policy.retention` 提供。当前仍仅供工程资料；不设置未经验证的患者资料保存期限。病例正文保留至归属用户主动删除；必要审计与删除凭证目前无自动到期删除，真实资料的期限、访问控制和物理保护继续由 P16 验收。

- `GET /cases/{case_id}/lifecycle`：认证后只返回本病例保留/删除状态、待处理 SDK 数量、时间和固定合同；无正文、路径或凭据。
- `DELETE /cases/{case_id}`：严格请求 `{ "snapshot_id": "当前快照 ID", "contract_version": "engineering-lifecycle-v1" }`。须有归属权限且快照一致。重复删除幂等；旧快照、其他用户、额外字段均拒绝。SDK 无删除/授权管理工具。
- 同一事务写入删除墓碑、使所有旧 run 失效并隔离在运行 job；删除该病例**全部输入版本**、导入文件名/摘要、预测/RL 产物、草稿、审核、发布、冻结配置及许可正文。审计无法提交则整体回滚，不声称删除成功。
- 保留 cases 归属/ID、墓碑/时间、run/job/task 的 ID、状态和关联、受控审计元数据与 hash、全局供应商预算。保留执行外壳使在途 worker 和 AgentTasks 能安全记录退出；用户提交的幂等字符串清除，输入/报告正文不在外壳中。事件/outbox 继续保留以追溯原因，不通过删除审计掩盖失败。
- 墓碑阻断本病例读取正文、更新、授权、新任务、迟到产物/提案/审核/发布；病例列表隐藏已删条目，已有 run 仅能返回失效状态/审计。其他病例不受影响。

状态含义：`RETAINED` = 未删除；`SDK_CLEANUP_PENDING` = 本地账本正文已移除但仍有登记 SDK 目录未确认清理；`LOCAL_CONTENT_REMOVED` = 账本正文已移除且登记 SDK 目录无待清理项。**最后一种状态也不表示所有备份、磁盘残留、进程内存和外部副本已擦除。** DELETE 返回 `local_content_removed` 与 `sdk_pending`，不能把“删除请求已接收”当作全部清理成功。

桌面资料区有明确的删除说明及未预选确认框，确认当前病例后才调用 DELETE。删除成功移除当前页面的正文；不确定响应保留重试提示，重试同一删除不会重复执行模型。原生构建已通过，但本批未实点原生窗口；全部 WebView 缓存、异常退出内存/共享电脑保护仍在 P16 范围。

## SDK 实际留存与清理

只读历史盘点发现 SDK 配置、backups、sessions 等文件；不能把 `no-session-persistence` 解读成无落盘。新报告/双 reviewer/预测 Agent 的宿主为每个工作目录登记 `case/run/job/session/ledger_scope`，登记事件提交后启动 worker。工作目录仍在 `runtime/sdk-smoke/sessions/<随机 ID>/`，`CLAUDE_CONFIG_DIR` 指向其中的 config，SDK `TMPDIR` 指向其中的 tmp；独立 worker 结束后、Core 接受成功输出前清理整个目录。

正常完成、取消、超时/错误、撤回或删除造成的中断均通过宿主 finally 回收。清理失败记 `CLEANUP_FAILED`，拒收本次暂存输出并要求处理残留后再使用该病例；已有目录冲突记 `PATH_CONFLICT`，不删除无法确认由本次创建的内容。路径及祖先符号链接拒绝跟随。外层服务在持有本账本独占锁并隔离中断 job 后，重试属于本账本路径的登记目录；失败则不启动服务。这个恢复入口不是可以对正在运行的服务任意调用的管理 API。

备份复制到另一账本路径不会让恢复程序删除原库的目录；未解决的记录保留为待处理，不冒充已回收。清理状态及事件也需事务提交，审计失败不能登记报告成功。目录删除不保证 APFS/SSD、系统快照或进程内存的不可恢复擦除；SQLite 启用 secure_delete，但不将它当成 WAL、文件副本或物理介质删除的充分证明。

已有历史会话与低层 SDK smoke/test 目录未登记病例归属，仍保留，**不得自动猜测属于某病例而批量清除**。本批只按元数据盘点；新报告/审核/预测 Agent 由上述宿主管理。旧调试、测试导出和人工复制的文件是独立副本，并未因 DELETE 自动清理；真实资料接入前须完成 P16 的副本治理。

## 撤回、备份、日志与供应商边界

| 操作/位置 | 已实现行为 | 保留边界 |
| --- | --- | --- |
| 撤回外发授权 | 阻断后续请求、流式/工具检查与待办结果；SDK 返回后清理登记目录 | 不删除已完成本地正文，不是远端擦除 |
| 本地正文删除 | 墓碑、撤销许可、正文删除和审计同事务，阻断旧任务 | 必要受控审计/hash/执行元数据继续保留 |
| 删除后的账本备份 | SQLite 一致性复制保留墓碑，恢复后不能读取/重用已删病例 | 没有新增自动备份服务；恢复测试使用隔离副本 |
| 删除前的备份 | 新 Core 实例不能复活旧外发许可，必须重新授权 | **内容仍可能存在/恢复**；未实现跨所有旧备份的删除传播，须在真实资料接入前由 P16 对账治理 |
| 预算/测试导出/旧目录 | 预算只存计数和金额；本轮不删旧测试证据或预算 | 删除病例不自动删除独立副本，不重置费用累计 |
| 供应商 | 本地只停止新请求并拒收失效结果 | 已发出的内容、本地断连前已在途请求不受本地擦除控制；未核验远端期限或删除承诺 |
| Observation | 未连接，无许可或上传入口 | 不将本地审计当成已接通外部服务 |

历史收费 smoke 脚本没有隐式授予许可；不要为恢复上下文反复运行或重置预算。API 不回显输入错误内容、CLI 服务关闭访问日志；SDK stderr 丢弃，宿主仅记录受控元数据。外部供应商保留期限、法规合规、完整加密/密钥管理、自动保留到期、备份/缓存/内存彻底擦除等仍未验收，不因工程删除合同完成而开放真实个人健康资料。
