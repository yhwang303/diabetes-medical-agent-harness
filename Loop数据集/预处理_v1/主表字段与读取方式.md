# 患者主表：字段与训练读取方式

每位名册患者一个`患者数据/LOOP_XXXXXX.parquet`，相同ID的`患者资料/*.json`与`事件记录/LOOP_XXXXXX/`属于同一人。Parquet保留类型/空值且压缩高效，比把数千万行拆成Excel更合适。无CGM者保留空主表并在索引说明；不要把空表计作训练患者。

## 一行的准确含义

`t=timestamp_utc`是研究决策网格点。CGM/碳水/运动等观察格为`(t−5分钟,t]`；胰岛素过去区间为`[t−5分钟,t)`，下一动作/结果区间为`[t,t+5分钟)`。普通Bolus恰好发生在t时属于下一剂量区间，不在前后格重复计入。原始事件精确时间另存，分箱不是将事件真的移动到了t。

| 字段 | 含义 | 是否能直接当t时状态特征 |
|---|---|---|
| patient_id | 带LOOP前缀的患者ID；跨来源不能共用裸编号 | 只作分组，不建议作为可记忆病人的数值特征 |
| timestamp_utc | 从原UTCDtTm按本次明确规则建立的网格时刻，未改本地时区 | 可用于时间间隔；本地昼夜需可靠时区 |
| split | train/validation/sealed_test/demo，患者级冻结 | 只作划分 |
| cgm_mmol_l | 本观察格最后一条无歧义实际读数；缺失NaN | 是 |
| cgm_mg_dl | 上列明确×18的等价单位，不是另一个测量 | 与mmol/L二选一 |
| cgm_mask | 该格有可用真实CGM值 | 是；0位置不能计入实测损失 |
| cgm_physical_present | 有CGM记录，即便因冲突/来源未验证不可用 | 质量标志 |
| cgm_conflict | 最后观测时刻是否有不同读数冲突 | 质量标志 |
| cgm_observed_time | 被选记录的真实发生时刻 | 是 |
| cgm_source_ref | 原文件、RecID及可用时的逻辑记录序号 | 追溯，不作数值特征 |
| cgm_readings_in_bin | 本格内不同原时间的记录数 | 质量标志 |
| cgm_age_s | t减该格记录真实时刻的秒数 | 是，缺值保留NaN |
| seconds_since_valid_cgm | 距最近可用真实CGM的秒数，不复制其血糖值 | 是 |
| cgm_segment_id | 本患者按>1小时CGM缺口划分的片段；长空档为0 | 分段用 |
| cgm_history_24h_gap_le1h | 过去24小时是否处于不跨>1小时缺口的CGM片段 | GlucoFM风格24h上下文筛选标志，不等于整日无缺值 |
| basal_rate_at_t_u_h | t时已重建基础速率 | 属于原行为策略当前动作相关量，不放入待预测动作前的状态 |
| basal_action_u_h | 整个下一5分钟固定且无歧义的基础速率；否则NaN | **动作标签**，不漏进状态 |
| basal_u_next_5min | 下一5分钟完整实际基础区间积分的U数 | **动作/暴露结果** |
| basal_known_partial_u_next_5min | 下一格仅已知部分的积分，不是完整剂量 | 质量审计，不可代替上列 |
| basal_coverage_s_next_5min | 下一格无歧义基础率覆盖秒数 | 后验资格，不能当t时输入 |
| basal_conflict_s_next_5min | 下一格异速率重叠秒数 | 后验资格 |
| basal_invalid_s_next_5min | 下一格被异常事件覆盖的秒数 | 后验资格 |
| basal_u_prev_5min | 过去5分钟完整基础量，未知为NaN | 是 |
| bolus_event_count_next_5min | 下一格有效普通/延长Bolus起始事件数 | 未来共同干预信息，不作t时输入 |
| bolus_recorded_u_next_5min | 下一格记录Bolus量（普通事件＋延长部分）；无记录为NaN | 未来共同干预信息 |
| bolus_recorded_u_prev_5min | 过去5分钟记录Bolus量；无记录NaN，明确零事件可为0 | 是，附是否记录的mask；不宣称生理零 |
| bolus_ambiguous_next_5min | 下一格存在已识别Bolus歧义 | 后验资格 |
| bolus_log_absence_is_unknown | 下一格没有可用Bolus记录，不可认定实际没注射 | 不作t时输入；过去状态需按时间移位 |
| insulin_logged_total_u_next_5min | 仅在日志完整假设下，基础量＋记录Bolus；基础/已知Bolus歧义时NaN | 条件性暴露，不是RL基础率动作，也不是一次注射量 |
| carbs_recorded_g_prev_5min | 观察格里无歧义碳水记录合计克数；未记录NaN | 仅事件时间假设下可用；实际录入时刻不明需敏感性研究 |
| carb_event_count_prev_5min | 上述有效记录事件数；0是无记录，不是0g | 记录mask |
| carbs_ambiguous_prev_5min | 观察格有碳水冲突或其他不可用记录 | 质量标志 |
| exercise_event_count_prev_5min | 观察格有效运动事件起始数；具体时长/距离/强度在事件表 | 记录mask，不是全天未运动的证明 |
| wizard_iob_u | 观察格最后一条有来源的计算器IOB估计；不前向填充 | 可选、来源依赖；不是全患者IOB真值 |
| basal_bolus_history_6h_ok | 前6小时完整基础区间且无已检出Bolus歧义 | 资格标志，不能证明全部额外注射均被捕获 |
| cgm_history_6h_gap_le1h | 前6小时CGM不跨>1小时断段 | 资格标志 |
| in_study_window | 当前动作区间在本次保守研究日期范围内 | 资格标志 |
| rl_snapshot_eligible | 当前状态/动作符合本次条件，不要求下一CGM可用 | 可用于进一步审核的状态-动作样本 |
| rl_transition_eligible | 当前/下一CGM均真实可用且其他要求满足 | **本次离线RL transition读取入口** |
| physiology_candidate_only | RL条件外另有可用体重、近6h餐食记录 | 仅候选，不表示生理模型辨识合格 |
| episode_id | 连续合格transition的小段编号，本患者内有效 | 数据连续性分组；末尾不是临床终止事件 |
| extreme_basal_rate_gt20 | 基础率高于本次保守20U/h筛查线 | 复核标志，非临床阈值 |

## 怎样读取

1. 先读`患者索引.csv`或`审计/rl_patient_manifest.csv`，按split挑选患者。不要在同一患者内部随机拆训练/测试。
2. 加载完整患者主表，再按`rl_transition_eligible`挑选目标行。**不能先删掉缺失/不合格行，再把剩下的相邻行当作相邻5分钟。** 历史窗口保留原始时间网格、NaN和mask。
3. 当前动作标签取`basal_action_u_h`，如模型需要5分钟U数则取`basal_u_next_5min`；两者在本任务中有明确等价关系。不能用`insulin_logged_total_u_next_5min`替换基础率动作。
4. 状态只用当前及过去观察、过去基础量/记录Bolus、缺失mask；所有`next`列、当前行为动作、未来问卷与阶段统计都不准进入状态。未来Bolus可作为已记录的共同干预分析变量，但不能假定新策略下它仍会原样发生。
5. 数据格中缺失值保持NaN。训练框架必须处理mask；若构造张量必须使用数值占位，必须同时传mask并屏蔽相应目标/损失，不能把占位当真实血糖。训练归一化统计只能从train患者估计。
6. 6h是本次状态窗口选择；若使用GlucoFM风格24h编码器，再要求`cgm_history_24h_gap_le1h`并读取288个格。时间嵌入/时间段编码留到训练时，此处未计算。

`代码/读取单个transition.py`演示如何从完整患者主表读取历史、动作和下一历史，不训练模型、不填补值。训练可从BC开始验证数据接口，再采用适合部分可观测、有行为支持限制的保守离线RL；本次没有证明任何算法效果。

训练manifest的episode末尾只表示数据资格边界，不应直接设置为“患者临床终止”。是否bootstrap、如何处理截断、延迟奖励与不完整反事实信息，需要训练方案明确。
