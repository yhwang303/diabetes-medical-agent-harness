# Loop患者级预处理：最终审计与使用决定

2026-09-14。当前发布：预处理v1。只处理Loop；其他来源仅复核。原始47个官方文件未改写；没有CGM插值、向前/向后补值、平滑或模型训练。所有数值和掩码保留本地。

## 最终决定

**首版离线RL训练使用train划分中的225名患者、1,653,421条合格5分钟transition。** 患者清单和确切行范围已落盘，不再以先前的369人提名上限作为训练人数。

| 划分 | 有合格片段的患者 | transition数 | 用途 |
|---|---:|---:|---|
| train | 225 | 1,653,421 | 参数学习、仅从此组估计归一化统计 |
| validation | 55 | 424,866 | 模型/超参数选择 |
| sealed_test | 32 | 280,742 | 冻结后的最终评价；此次只做固定规则的数据完整性审计 |
| demo | 17 | 176,054 | 独立演示；不算训练或最终测试 |
| 合计 | 329 | 2,535,083 | 合计不是训练集大小 |

[全部患者索引](患者索引.csv)包含919人的保留/资格情况；[RL患者清单](审计/rl_patient_manifest.csv)明确上述329人的split；[episode行范围清单](审计/rl_episode_manifest.parquet)给出每个连续片段的起止行、下一状态行和患者ID。训练只能读取split=train，不能把四组重新混合。

这批数据**通过了本次冻结规则下的结构、配对、无插值和回顾性资格检查，可以开始BC/保守离线RL基线研究**。这不是“治疗日志已临床完备”或“闭环剂量已有效”的结论。现有预测器的训练来源未核实前，不用于声称全链独立测试；新预测器/生理模型/RL必须共用这份患者划分。

## 1. 最终目录和每人一个文件

2026-09-14批次45补充：[RL数据集/train](RL数据集/train/)已单独放置225份训练患者表，另有validation/55人、sealed_test/32人、demo/17人独立文件夹。[使用说明](RL数据集/README.md)说明目标行筛选和当前未验证问题。它们与全量归档逐字节一致，保留完整历史与原行号；没有新增训练样本或重做划分。

```text
├── 事件记录/LOOP_XXXXXX/          去重后的CGM/胰岛素/餐食/运动等事件与基础区间

├── 患者表预览_训练患者.csv        训练患者的一小段，便于直接阅读
├── 审计/                         固定split、训练清单、校验结果、文件hash

```

主表约3.22GB，共93,683,244个5分钟网格行，来自851名有CGM的患者；其余68人保留资料与空主表。不要把全部网格行当训练样本，也不要把文件大小当独立有效信息量。

“每人一个Parquet主表”比每人一份Excel更合适：可保留列类型/NaN、按列读取且压缩高效。原始事件和低频资料单独保存，是因为同一时间可能有多笔事件，而季度问卷、样本检验和设备配置不能被强行复制成每5分钟都已知的事实。

[主表全部字段与读取说明](主表字段与读取方式.md)详细定义42列及输入/动作/未来结果的区别。[训练患者CSV预览](患者表预览_训练患者.csv)只用于阅读，不是完整训练集。

## 2. 实际处理与验证

### 身份和来源

- 全量读取14个设备事件TXT：164,593,278行；另归档名册、问卷、上传信息、检验、研究事件等小表及IssueRpt。
- 逐条核对设备PtID、名册和ParentLOOPDeviceUploadsID对应患者：162,464,921条通过，2,128,357条找不到上传父记录；没有发现事件患者A关联到上传患者B的记录。
- 缺失父记录并不等于发现串人，但不能把它写成来源已验证。不可用记录保留在隔离/事件层，并阻止其被当成已验证测量/暴露；不借别人的资料补齐。
- 最终全部93,683,244行检查了单一患者ID、split、唯一时间与连续网格；81,717,681个可用CGM格逐值匹配对应患者的原事件来源、数值与真实时刻。
- 患者划分先于切网格/片段。没有把同一人拆到训练与测试；原始不同研究来源的裸编号不能混用。

### 去重和冲突

按患者、精确事件时间和本表核心语义折叠相同记录，保留代表来源、等价记录数及内部原事件。实际折叠的额外行：

| 事件 | 折叠额外行数 |
|---|---:|
| CGM（不含校准） | 19,628,322 |
| Basal | 125,072 |
| Bolus | 308,749 |
| Food | 13,549 |
| Exercise | 4,800 |
| Wizard | 649 |
| BGM | 37,494 |

同一时刻不同CGM值不取平均；同刻不同Bolus/碳水不盲目相加。基础输注的同速率重叠按区间并集合并，不重复积分；异速率重叠保留冲突，不由任意记录编号决定谁覆盖谁。

**去重边界：** 公开表不是完整原生泵事件UUID日志，“同人同刻同实际分量”作为重复上报的等价规则仍是一项数据假设；无法由公开字段绝对排除真实同刻同量的多次给药。等价计数与原来源保留，不能把它描述成临床原生事件身份已全面确认。不同记录值的歧义已阻断；完全相同事件的额外临床辨别力不是此次转换能创造的。

IssueRpt有4条复杂逻辑记录列宽异常，原始内容已保留隔离；其他正确列宽报告的Latin1映射只用于可逆保存，不声称原始文本编码问题已解决。配置/问卷仅按患者归档，不把最后一次配置扩散到全历史。

### 无插值与因果分箱

依据用户提供GlucoFM的§3.1、附录A.1/C.1–2：短缺口保留NaN与mask，超过1小时断段。保留原始时间，不实现训练阶段的昼夜/周期编码、归一化或平滑。

论文会平均同格多次读数；本次明确改用结束观察格内的最后一条实际值，并保留该值的真实时间和source_ref，避免构造新的血糖数值。决策t只读取t及以前的CGM，不把t之后的读数贴回t。缺失CGM不能计算实测目标/奖励；未作为当前/下一真实观测的行仍保留给掩码历史编码。

原公开日期按患者去标识化平移，时区缺失不能凭空修复。网格UTC相关时刻不自动等于真实本地昼夜。未来做不同时间段编码时须区分绝对钟点、相对时间和时区可用性。

### 独立剂量核对

所有合格transition检查当前/下一实测CGM、6小时前史、无冲突完整基础暴露、固定5分钟基础率、研究范围与患者资格。另对40名患者做115次独立区间积分，直接从事件交集和中点有效区间计算，核对完整量、部分量与冲突秒数，没有复用主构建器的区间扫描算法。全部通过。

12项单元/对抗测试及合成整患者链路通过，包括同速率重叠不双计、异速率冲突、暂停零、毫秒缺口不补齐、跨患者隔离、事件边界、6小时前史不读未来、缺失CGM保持NaN。真实患者读取器也已验证72格历史、动作和下一历史的构造。上述结果证明数据处理实现，不是临床验证。

完整机器可读证据：[final_audit.json](审计/final_audit.json)、[来源与代码hash](审计/provenance.json)、[摄入日志](审计/ingestion.log)、[处理日志](审计/build.log)、[复核日志](审计/verification.log)。初期大表导出两次触及12GB内存限额，随后改用20万行分块完整跑通；错误保留，没有吞错跳行。

## 3. 速率是不是剂量：已经同时给出

基础输注有两个不同量：

- `basal_action_u_h`：接下来5分钟维持的基础率，U/h。
- `basal_u_next_5min`：该5分钟实际基础输注区间积分，U。

例如基础率1.2U/h完整持续5分钟，区间量=1.2×5/60=0.1U。跨时间格的事件只按真实交集积分；缺失区间不补率、不无限延长。暂停事件省略Rate时按官方明确语义赋0并保留标记，其余未知Rate不这样处理。依据：[Tidepool basal定义](https://developer.tidepool.org/data-model/device-data/types/basal/)、[暂停定义](https://developer.tidepool.org/data-model/device-data/types/basal/suspend.html)。

Bolus.Normal/Extended本来就是U，Expected值是预期量，不能替代实际量。两者分列。`insulin_logged_total_u_next_5min`只是在“日志完整”的条件下汇总基础量和记录Bolus；缺少事件不等于证实没有额外注射，不能把这个条件量写成确定的全身胰岛素暴露。

**这些U数是泵在一段时间内的输注量，不是让患者一次注射的建议。** RL首版动作仍是基础率；不要把基础率、区间量、餐时Bolus混成一个含义不明的“剂量”列。

本次动作标签是重建的等价5分钟持有速率，不宣称原控制器恰好在网格t发出指令。若5分钟内实际改变了基础率，则保存积分暴露，但不把平均率冒充t时的一次策略动作。

## 4. 缺food/exercise，究竟怎么处理

**保留缺失模态患者进入符合其他条件的离线动作池；不填0，不统一要求全模态。餐食信息的缺失对生理辨识比对接口/回顾性行为训练更关键，不能混成一个门槛。**

在研究时段内“至少有一条有效记录”的实际敏感性：

| 额外门槛 | 全划分患者 / transition | train患者 / transition |
|---|---:|---:|
| 不要求food/exercise存在 | 329 / 2,535,083 | 225 / 1,653,421 |
| 必须有food记录 | 326 / 2,527,103 | 223 / 1,651,840 |
| 必须有exercise记录 | 179 / 1,426,426 | 125 / 970,638 |
| 两者都必须有 | 179 / 1,426,426 | 125 / 970,638 |

强制两者都存在会删除100名训练患者（44.4%）和682,783条训练transition（41.3%）。这并不能证明余下患者的每餐/每次运动完整，还可能偏向更愿意记录、更多使用可穿戴设备的人。

只有3名合格患者在研究窗口内没有有效food记录，train中为2名、1,581条transition。即使去掉他们，**其余患者也只是“有记录”，不是“每一餐都记录”。** 不应把筛掉这3人当成解决了未记录进食问题。

从第一性原理，未来血糖还受当前体内活性胰岛素、餐食吸收、运动与胰岛素敏感性影响。CGM＋药量是核心，却不能保证状态完全可观测。掩码帮助模型识别“我不知道”，不能消除遗漏变量或行为策略混杂。因此：

- **离线行为/策略研究：** 用真实CGM历史、已重建胰岛素历史和缺失mask；food/exercise为可选输入，做同一患者划分下的模态消融。数据可用于BC与保守离线RL开发，但不能把拟合历史控制行为等同于最优策略或因果效果。
- **动作条件生理模型：** 需要进一步处理制剂、体重、餐食可信度、初始状态/作用尾部和未观测扰动。1,537,138行仅标记为有体重和近6h餐食的候选，不代表完整meal ground truth；**本轮通过独立生理辨识验证的患者数为0**。
- **反事实闭环：** 新基础率改变后，未来血糖、纠正Bolus和救援碳水不能照搬历史。必须另有经独立验证的响应模型和反馈规则。本次没有构建这种环境，也没有证明临床剂量建议有效。

[ReplayBG原始研究](https://pubmed.ncbi.nlm.nih.gov/37368794/)可作为后续生理辨识依据，但不能从“具备几列字段”直接跳到“数字孪生可信”。

## 5. 是否真的适合训练：重要的不利结果

387名患者通过基线治疗/人群门槛，最终329名具有合格transition；另外58名在本次全部时段/来源/历史/动作条件下没有合格transition。所有排除信息保留在患者索引及对应资料文件，不把未知情况改成阴性。

共有667,960个连续合格小段，段长中位数仅2个transition（10分钟），90分位8个（40分钟），99分位28个（140分钟）；最长758个（约63.2小时）。至少1小时的段40,860个；至少6小时1,190个；至少24小时只有11个。

这反映的是**所有RL资格条件连续通过的长度**，不是说CGM本身只有这么短；5分钟内基础率变化、暴露冲突和真实观测要求都会截断合格动作段。完整原事件/网格仍在。2,025,706条合格transition另具有不跨>1小时缺口的24h CGM上下文。

因此最终使用方式是：

1. 使用225名train患者的完整主表，按资格标记取离线transition；在完整网格中回看6h或24h历史，保留NaN/mask。以患者均衡采样控制长记录患者的影响。
2. 先建立BC与短转移的保守离线RL基线。不要把碎片末尾都当成临床terminal，也不要把2,535,083条短转移写成同样数量的独立长期实验。
3. **不能把这批离线数据直接交给PPO做“真实环境交互”，也不能据此声称已有大量完整多日反事实rollout。** 延迟药效、状态部分可观测、动作支持和短片段自举误差都需后续实验检验。
4. 生理模型与仿真闭环保持未验收；当前Harness仍需真实来源/双模型证据合同适配，不会因数据已对齐而自动获得给药发布资格。

冻结规则全文见[处理规则](处理规则.md)。6个月研究窗口、6小时前史、20U/h复核线都是本次保守研究设计，不是临床安全保证；没有在看见结果后放宽这些规则来增加人数。

## 6. 其他数据集复核

**“现在不混入”不等于“永远不能合并”。** Ohio是后续补充离线动作池值得优先复审的来源；体重占位主要阻碍需体重的生理模型。DCLP3仍需解决指令基础率与实际输注的区别、延长Bolus时间；IOBP2需正确对应前一控制步的已递送量并处理不同控制任务，保持整源留出是实验设计选择；UOM仍有区间/冲突/作者已有插补掩码缺失问题。

详见[其他来源仅复核报告](其他数据集能否合并_仅复核.md)。本轮没有处理、改写或合并这些来源。
