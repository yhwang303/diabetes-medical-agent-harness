# Loop预处理v1，先看这里

**最终训练主池：225名train患者，1,653,421条合格离线RL transition。** 另有55名validation、32名sealed_test、17名demo患者；合计329名有合格片段，不能全算训练。

**直接使用：[训练目录——225名患者，每人一张表](RL数据集/train/)。** 其他划分已分别放在[RL数据集](RL数据集/README.md)。每张表保留完整历史，只有 `rl_transition_eligible=True` 的行作为训练目标，不可将全表每行都用于剂量学习。这是离线基线研究数据资格，不是闭环模型有效性证明。

- [最终审计报告与使用决定](最终审计报告.md)：结果、食物/运动缺失的真实损失、速率/剂量区别，以及能训练到哪一步。
- [患者索引.csv](患者索引.csv)：所有919名册患者的文件和资格；851人有CGM主表，其余为空表。
- [全量患者归档](患者数据/)：919名册患者每人一个Parquet，保留NaN/mask；这不是训练专用目录。
- [训练患者CSV预览](患者表预览_训练患者.csv)：看你希望的“id、时间、CGM、剂量…”结构。
- [主表字段与读取方法](主表字段与读取方式.md)：完整字段含义、如何不把未来数据放进状态。
- [RL患者清单](审计/rl_patient_manifest.csv)与[episode行范围](审计/rl_episode_manifest.parquet)：训练精确读哪些人和哪些行。
- [其他来源合并条件复核](其他数据集能否合并_仅复核.md)：仅check，没有合并。

原始数据仍在上一级`原始数据`，内容未改。`内部`只是可复查的处理中间数据，`事件记录`提供溯源；日常从患者主表开始即可。本次未插值、未训练模型，生理仿真/临床闭环并未验收。
